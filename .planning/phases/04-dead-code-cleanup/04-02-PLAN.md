  <action>
    Read the ENDPOINT-INVENTORY.md produced by Plan 01. For every route with status "orphan":

    1. **Remove the route handler** from its controller file (delete the method and its decorators).

    2. **Cascade to service layer** per D-01:
       - Check if the service method called by the removed route is used elsewhere (grep for method name across all `.ts` files).
       - If the service method has NO other callers, remove it from the service file.
       - If removing the service method makes any private helper methods unreferenced, remove those too.

    3. **Cascade to DTOs** per D-01:
       - Check if DTOs used only by the removed route handler are referenced elsewhere.
       - If a DTO class has NO other imports, delete the DTO file or remove the class from a shared DTO file.

    4. **Handle module-level cleanup** per D-02:
       - If ALL endpoints in a controller are removed, remove the controller file.
       - If a controller file is removed AND it was the only controller in the module, check if the module has other exports used by other modules.
       - If the module has NO remaining exports used anywhere, remove the module and its import from `src/app.module.ts`.
       - Per D-02: do NOT delete entire modules preemptively. Only remove if genuinely empty after endpoint removal.

    5. **Handle the root GET / route** in `src/app.controller.ts`:
       - If ENDPOINT-INVENTORY.md marks it as orphan, remove it.
       - Keep `GET /health` (used by Docker healthcheck and CI).

    6. **DB columns** per D-09: Do NOT create any DROP COLUMN migrations. Only remove TypeScript code (entity properties can stay if they map to existing columns — the column remains in the DB).

    7. **Known likely orphans** (confirm from inventory before removing):
       - `POST /files/presign` — S3 presigned URL generation, no consumer found
       - `POST /files/complete` — S3 upload completion, no consumer found
       - `GET /` — root health-check-like route (if confirmed orphan)

    8. **Commit strategy**: Group removals by module. Each commit message must explain WHY the endpoint was removed:
       - Example: "remove(files): delete presign/complete endpoints — no Admin UI or MCP consumer per endpoint audit"

    9. **After all removals**, run:
       - `npm run build` to verify compilation
       - `npm run lint:fix` then `npm run lint:js` to fix/verify lint
       - `npm test` (if tests exist) to verify no regressions
