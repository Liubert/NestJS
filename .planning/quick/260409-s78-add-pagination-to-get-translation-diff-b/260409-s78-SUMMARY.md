# Phase quick Plan 260409-s78: Add Pagination to Get Translation Diff Summary

**One-liner:** SQL-level LIMIT/OFFSET pagination with CTE aggregate counts for the sandbox diff endpoint, plus MCP tool updated to pass page/limit params and show "Showing X-Y of N (page M of P)" output.

## What Was Built

The sandbox diff endpoint previously returned all entries (up to 1784 for large projects), causing MCP context overflow. This plan adds SQL-level pagination using CTEs with window aggregation so summary counts (added/changed/deleted) always reflect the full filtered dataset, not just the current page.

### Backend Changes

**`src/modules/translations/dto/diff-query.dto.ts`** (new)
- Extends `PaginationDto` (page=1, limit=50 defaults)
- Optional filters: `namespace`, `locale`, `status` (added|changed|deleted)

**`src/modules/translations/sandbox.service.ts`**
- `getDiff()` signature extended: `page`, `limit`, `filters?: { namespace, locale, status }`
- SQL refactored to use four CTEs: `production`, `sandbox`, `diff` (with CASE for status), `filtered` (WHERE clause for optional filters), `counts` (COUNT(*) FILTER aggregates)
- Single query: cross join `filtered` rows with `counts` row for complete aggregate data
- Returns `meta: { page, limit, total, totalPages }` alongside existing fields

**`src/modules/translations/sandbox.controller.ts`**
- `diff()` method now accepts `@Query() query: DiffQueryDto`
- Passes `query.page`, `query.limit`, and filter object to `getDiff()`

### MCP Changes

**`mcp-server/src/tools/diff.ts`**
- `DiffResponse` interface updated to include `meta` object
- `get_translation_diff` tool description updated to mention pagination
- `page` and `limit` added to tool schema with defaults (1 and 50)
- Client-side `.filter()` calls removed — filtering now sent as query params to backend
- Output includes "Showing X-Y of N (page M of P)" when paginated
- Output includes "Next page: call with page=N" hint when more pages exist
- `validate_translations` passes `{ limit: 5000 }` to fetch full diff for validation

## Decisions Made

1. **CTE-with-aggregate approach**: Single SQL query handles both pagination and summary counts. The `counts` CTE computes `COUNT(*) FILTER (WHERE status = 'added')` etc. on the full filtered set, then cross-joins with each page row — avoids two separate queries.

2. **Summary counts reflect filters, not full diff**: When filtering by namespace/locale/status, the `total`/`added`/`changed`/`deleted` counters reflect only the filtered set (not the entire project diff). This is intentional — the user sees counts for what they're currently viewing.

3. **validate_translations uses limit=5000**: The validation tool needs the full diff to detect partial translations across locales. A high limit (5000) ensures it gets everything in one call without refactoring to multi-page fetching.
